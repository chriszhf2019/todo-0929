# 手机助手（自己用）· 最小闭环

手机当眼睛和手（无线 adb），Mac 当大脑（本地 Ollama 视觉模型）。

```
截屏 → 视觉模型看屏输出动作 → adb 执行 → 再截屏验证 → 循环
```

## 一次性搭建

```bash
# 1. 装 adb
brew install android-platform-tools

# 2. 拉一个视觉模型（二选一）
ollama pull llava            # 默认，~4.7G，稳定
ollama pull qwen2.5vl:7b     # 更强，中文+结构化输出更好，~6G

# 3. 手机（Pixel 9 Pro Fold）开启无线调试
#    设置 → 关于手机 → 连点「版本号」7 次 → 开发者选项 → 无线调试
#    点进「无线调试」→「使用配对码配对设备」，记下 IP:端口 + 6 位配对码
adb pair <配对IP:端口>        # 输入配对码
adb connect <连接IP:端口>      # 注意端口和配对端口不同
adb devices                    # 应显示你的 Pixel（device 状态）
```

## 运行

```bash
cd phone-assistant

# 自动模式：模型自己决定并执行（可能点偏）
python3 assistant.py "打开设置"

# 副驾模式（推荐）：模型给建议 + 理由，你确认后才执行
python3 copilot.py
MODEL=qwen2.5vl:7b python3 copilot.py "打开微信"
```

副驾模式交互：
- `y` / 回车 → 执行建议动作
- `s` → 跳过，让模型重看
- 输入任意文字 → 当作新目标
- `q` → 退出

## 两个模式的区别

| | assistant.py（自动） | copilot.py（副驾） |
|---|---|---|
| 执行时机 | 模型自己决定 | 你确认后 |
| 输出 | 只有动作 JSON | 屏幕描述 + 理由 + 动作 |
| 坐标点偏时 | 白点一下 | 你读描述就能纠正 |
| 适合 | 跑通验证 | 日常用 |

## 当前能力边界（最小闭环）

- 支持动作：`tap` / `swipe` / `back` / `home` / `open_app` / `done`
- **不含中文输入**：`adb shell input text` 不支持中文，需 ADBKeyboard（后续再加）
- **坐标可能点偏**：通用视觉模型像素精度有限，多步会自行纠正，属正常

## 结论（2026-09-25 实测）

**闭环已端到端跑通**，核心结论：

| 维度 | 结论 |
|---|---|
| 基础设施 | ✅ adb 连接、截屏、视觉模型调用、动作执行、循环，全部可用 |
| **读屏准确度** | ✅ **准确**（实测：屏幕是「记言 Todo」，模型正确描述为「信息管理应用，有微信记录和待办」） |
| 动作决策 | ⚠️ 弱（通用 VLM 不擅长「该点哪个」+「多步规划」） |
| 正确形态 | **副驾**——读得准 + 人做判断 |

**三层架构（由快到慢、由确定到智能）：**

1. **规则直达**：`打开X`（~90 个应用，见 `apps.py`，包名从设备权威导出）、`回到桌面`、`返回`、`锁屏/亮屏`、`音量±/静音`、`截图`、`下拉通知栏`、`亮度 50`、`拨号 号码`、`打开网址 url`、`wifi/蓝牙/开发者选项`、`最近任务` 等——全部确定性 adb 命令，秒回、零模型调用、100% 可靠。
2. **uiautomator 精确点击**：模型建议点元素时，用无障碍树拿到每个元素的精确中心坐标（`tap_element`），模型只选编号、不猜像素。
3. **模型读屏 + 建议**：开放式请求走 qwen2.5vl 读屏描述 + 人确认。

**根因**：`qwen2.5vl:7b` 是通用视觉模型，不是 GUI 操作专用模型。它会「看」，不会「精准点」。

**已搁置（后续再说）**：多步自主规划（打开微信→找联系人→发消息）、专用 GUI agent（MobileAgent / MobileUse / GUI-Owl）、更大模型（qwen2.5vl:32b）。

### 过程中踩过的坑（已修复）

1. 折叠屏 `screencap` 多显示警告混入 PNG → 改用 `shell screencap` + `pull`
2. 视觉模型默认上下文 4096 不够 → `num_ctx=16384`
3. 模型输出畸形 JSON（`click` / `x=[x,y]`）→ 动作归一化
4. `y` 被当新目标 → 修 input 分支
5. adb 子进程抢占 stdin → `stdin=DEVNULL`
